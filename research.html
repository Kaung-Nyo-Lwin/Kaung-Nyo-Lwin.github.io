Research · Master’s thesis

L2BC: small models, verifiable rewards.

A reinforcement fine-tuning framework that teaches compact code models to turn a question and its tables into a correct chart in one generation. Every reward comes from rules that execute the program and check what the chart actually shows. No LLM or VLM judge is involved.

  • Asian Institute of Technology
  • 2026
  • Reinforcement learning
  • Text-to-visualization

The problem

A chart can render without errors and still show the wrong data. To get it right, a model has to select and join tables, transform values, choose an encoding, and write code that runs.

Reinforcement learning has reached text-to-visualization, but with rewards from learned reward models or from LLM and VLM judges. A judged reward makes a policy only as correct as its judge can recognise, and its scores are hard to reproduce or audit. L2BC asks whether the reward can come from verification instead.

How it trains

L2BC fine-tunes Qwen2.5-Coder 1.5B and 3B with GRPO and LoRA adapters, using the TRL trainer. A system prompt asks for the whole procedure in one pass, as a program with seven commented sections, from imports and data loading to display.

  1. 01 / GENERATE

    Sample programs

    For each question and its tables, the policy samples a group of candidate visualization programs.

  2. 02 / EXECUTE

    Run and render

    Each program runs and renders its chart, or fails. Execution failures are part of the signal.

  3. 03 / VERIFY

    Parse and check

    Rules parse the chart back into a schema of type and encoded data and check it against the ground truth. A second rule checks the program against the workflow.

  4. 04 / LEARN

    Update and adapt

    Group-relative advantages update the policy. The verified reward’s expectation, called comfortability, sets the next epoch’s temperature, learning rate and reward shape.

Because the reward is verified, its expectation estimates the policy’s actual correctness, not a judge’s opinion of it. That is what makes it safe to steer training with.

Results

Trained on 192 VisEval queries with no judge in the loop, the best 3B configuration beats agentic pipelines built on a 7B model in a single generation. The best 1.5B configuration reaches parity with them.

  • +8.10 / +15.94points above the best 7B baselines on single- and multi-table queries, with about a third of nvAgent’s single-table invalid rate (4.40% vs 11.71%).
  • 58.55%single-table pass rate at 1.5B, within 1.32 points of nvAgent with a fifth of the parameters; 43.28% multi-table, level with CoML4Vis.
  • 31.20% → 59.03%single-table pass rate of the 3B model from base to verified training, mostly by removing execution failures.

What the work showed

  • No LLM is needed anywhere in the reward. A reward that consults only the human-curated chart specification already beats every 7B baseline at 3B after five epochs (66.84% single-table, 46.90% multi-table).
  • Comfortability matters at 1.5B. Removing any dynamic mechanism lowers every reward component. Standard GRPO with static hyperparameters reaches 42.47% validation legality, against 63.65% with comfortability. At 3B the effect is inconclusive.
  • Verification shows where it stops. The decomposed reward exposes the one aspect it never rewards, sort order, whose violations grow on unseen tasks. A model learns the checks it receives and can still miss what the specification leaves out.

The central trade. A verifier swaps the judge’s ceiling for a specification ceiling. It is exact where a ground-truth specification exists and blind where none does, so aesthetics still belong to a judge. Verified correctness plus a judged aesthetic term is the natural hybrid.

Limits

  • No judge-based reward was trained under identical conditions, so rule-based rewards are presented as a verifiable alternative, not one shown to dominate judges.
  • Chart rewards need human-curated specifications, and about 14–15% of queries still fail on data correctness.
  • One benchmark, one model family at 1.5B and 3B, and one run per configuration. The best configuration per scale was selected on the benchmark.

Citation
